# autotest

这篇文章提供`autotest.py`的功能以及实现细节等。

## 功能

当前正在开发的中国象棋引擎项目需要一个自动测试功能
以避免极其麻烦的人工测试
因此使用皮卡鱼进行自动对弈测试工作
自动、多进程地与皮卡鱼对局
收集胜、负、和、己方违规、对局超过长度限制、己方程序崩溃几种情况数据
以方便当前项目的开发工作

## 实现细节

作为自动测试模块，`autotest.py`提供以下功能（我们能够保证皮卡鱼引擎几乎不会出现任何异常）：

- 使用`pikafish.py`提供的功能运行皮卡鱼引擎。
- 提供相应的调整皮卡鱼搜索深度的选项（`--depth`）。
- 检测编译器环境，自动以最高优化等级编译并运行Chess98项目。
- 持续对弈，对局结束就结束二者进程新开一局，直到达到测试数量上限。
- 根据处理器情况自动决定同时进行多少进程测试（约`物理核 - 2`，即 `cpu_count // 2 - 2`）。
- 能够设置总测试量（`--count`，默认 100）。
- 能够处理异常情况，如程序崩溃、输出不符合预期等。
- 能够将结果实时写入日志文件内，对于己方违规、崩溃、对局超过长度限制等情况特别标明。
- **记录每一局的对弈过程**（着法序列），便于复盘分析。

其中某些事项如下：

- 源文件路径为`<PROJECT>/src/main.cpp`，C++17及以上三大编译器均能通过编译
- 编译路径`kits/__pycache__/chess98.exe`
- chess98到目前为止还没有写完，但预计支持uci/ucci双协议，这里按uci协议测试即可
- 由于还没有写完，可以用皮卡鱼代替chess98对弈来验证python有无bug，反正协议相同
- 若检测到`<PROJECT>/README.md`有`This project is being refactored now...`字样，则用皮卡鱼，反之正常用chess98
- 实时输出对弈结果
- 每个 UCI 引擎进程强制 `Threads=1`、`Hash=64`，避免多进程测试时超线程/多线程抢核导致结果失真
- **不在测试脚本里做三次重复检测**：重复局面由皮卡鱼自行判断，并通过评分体现

### 常量与路径

| 名称 | 含义 | 默认 |
|------|------|------|
| `MAX_PLY` | 对局半手数上限 | `400` |
| `NO_CAPTURE_DRAW_PLY` | 连续无吃子半手数达到此值判和（自然限着） | `120` |
| `LOG_PATH` | 汇总日志 | `kits/__pycache__/autotest.log` |
| `GAMES_DIR` | 逐局过程目录 | `kits/__pycache__/autotest_games/` |
| `CHESS98_EXE` | 编译产物 | `kits/__pycache__/chess98.exe` |
| `DEFAULT_GAMES` | 默认对局数（`--count`） | `100` |
| `DEFAULT_DEPTH` | 默认搜索深度 | `10` |

### 终局判定

- **胜 / 负**：对方（或己方）无合法着法（将被杀 / 困毙）
- **和**：
  - 引擎返回 `bestmove (none)`，或 UCI `score cp 0`（皮卡鱼对重复等局面的判和体现）
  - 连续无吃子达到 `NO_CAPTURE_DRAW_PLY`
  - 到达 `MAX_PLY` 且己方近期评估无显著优势
- **too_long（超过长度限制）**：到达 `MAX_PLY` 且己方仍有明显优势（`|cp| >= 300` 或 mate）却未能终局——需特别关注
- **illegal**：己方走出非法着法
- **crash**：己方引擎进程崩溃或未返回 `bestmove`

### 替身模式深度

重构标记开启时双方均为皮卡鱼：己方深度=`--depth`，对手深度=`max(1, depth - 3)`，
避免完全同强拖满局长、刻意规避重复导致统计全是和棋 / `too_long`。正式使用 Chess98 时双方深度相同。

### 对局过程记录

每局结束后写入 `GAMES_DIR/game_<id>.txt`，内容包括：

- 对局编号、结果、ply、己方颜色、说明
- 完整着法列表：UCI + 中文记谱（如 `炮八平五（b2e2）`）
- 便于对违规 / 崩溃 / 超长局做复盘

同一轮测试开始时清空/重建该目录，避免与历史局次混淆。汇总行仍追加写入 `LOG_PATH`。

运行方式：

```text
python -m kits.autotest
python -m kits.autotest --count 50 --depth 8 --workers 4
```
